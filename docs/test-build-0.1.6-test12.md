# 0.1.6 — 参数保留区（默认关闭）

本记录对应 0.1.6 正式版的开发验证；测试期版本号为 0.1.6-test12，功能与构建一致。

用于保护内部 Flash 模拟 EEPROM 的参数区：用户按页声明不擦写的地址范围，烧录时跳过这些页。功能**默认关闭**，不改变任何既有烧录行为。

## 交付

- **默认关闭**：关闭时不改变产品配置与配置指纹，旧批次与新任务行为完全不变；已保存的地址仅在开启后生效。
- **按页/扇区对齐**：保留区必须落在芯片实际擦除边界上，不做静默取整；部分覆盖页会直接报错，避免"以为保住了其实被擦掉"。
- **按设备组 + 容量分开保存**：key 形如 `414:262144`，换芯片或换容量不会套用另一颗芯片的地址。
- **整片擦除也跳过**：选择"整片擦除"时保留页仍排除在擦除计划之外。
- **固件冲突直接拒绝**：固件覆盖保留区时预检失败，界面提示"固件覆盖产品保留区；请检查固件与目标配置"，烧录按钮禁用。
- **批量配置指纹**：任务开始时冻结"芯片 + 算法 + 保留区"的配置 SHA-256；换板后若指纹不匹配则暂停并按原批次配置核对，实际擦除前再校验一次，避免批量中静默改用另一套保留区。
- 配置损坏（JSON 截断、非法 key、越界地址）会阻止烧录并提供重置入口；写入使用 `commit()`，保存失败不发布新配置。
- 支持包含结束地址的十六进制输入（`0803F800` – `0803FFFF`），内部转为半开区间；32 位顶端 `FFFFFFFF` 不溢出。

## 边界

- 只保护**烧录过程**不擦除。新固件启动后主动清空参数区仍会丢失，本功能不阻止。
- 不管理**外置 EEPROM**（24C02/24C64 等），它们不在内部 Flash 擦除范围内。
- 不修改读保护与 Option Bytes。
- 程序与参数共用同一页时无法保留；需要调整分区或实现备份恢复。

## 验证

构建与测试：`GRADLE_USER_HOME=~/.gradle ./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --offline`

- **178 项测试通过**（core 164 + app 14），0 失败 0 错误；`--rerun-tasks` 强制重跑结果一致。
- lint：0 errors / 13 warnings（既有构建工具与备份配置类告警）。
- core 新增 8 项保留区测试：默认关闭不改指纹、开启后并入固有保留区且排序不合并、含结束地址无损解析、越界/部分页/重叠拒绝不取整、非等长扇区使用实际边界、规划器跳过保留页且冲突拒绝、同芯片下保留区变化会改变配置指纹且可稳定复现。

真机验证（Xiaomi 25060RK16C / Android 17 API 37，ST-LINK/V2 J23，STM32F1 大容量 256 KB，UID `30FFD305-30554D36-43751243`）：

1. **负向 — 冲突拦截**：保留区 `0x08000000–0x080007FF` 与 Template.hex 起始页冲突，「开始烧录」容器 `enabled=false`，界面显示"固件覆盖产品保留区"。截图 `.local-validation/test12/conflict-blocked.png`。
2. **正向 — 保留页跳过并正常烧录**：保留区改为末页 `0x0803F800–0x0803FFFF`（在固件范围外），按钮恢复可用。任务 **#18** 真实烧录：擦除 35 页、写入 68.0 KB、**回读校验通过**、已复位并解除停核，用时 16.6 s。固件覆盖 `0x08000000–0x08011023`（35 页），与擦除页数一致，末页未被擦除。截图 `.local-validation/test12/reserved-region-flash-pass.png`。
3. **持久化**：`shared_prefs/reserved-regions.xml` 实际写入 `{"414:262144":{"enabled":true,"ranges":[{"start":134477824,"end":134479872}]}}`，与应用内显示一致。

**未覆盖**：批量换板的指纹暂停分支只有逻辑测试与独立审查，未在真实换板流程中触发验证（依赖多块同型号板）。
