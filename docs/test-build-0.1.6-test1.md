# Corn Flashing 0.1.6-test1

日期：2026-10-26。versionCode 8。基于 v0.1.5 / ff4fe9d 的本地修复测试包，尚未发布 GitHub Release。

## 修复

- GET_VERSION 版本字改为大端解析；NRST 参数修正为 0/1/2；SWD 成功状态严格检查 0x80。
- F1 Flash 采用明确的 WRITEMEM_16BIT 命令。擦除前要求 ST-LINK/V2 J26+，不支持则报错且不擦除。
- 真实 F1 算法移入可测试核心，清楚区分寄存器 32 位写和 Flash 16 位写。
- 奇数地址/尾字节统一组成对齐半字，跨 HEX 记录不会重复编程同一半字；填充不得越界或触碰保留区。
- 单字节 MEM8 读取按 V2 的两字节应答接收，禁止吞掉内存读写状态错误。
- 在擦页、每次半字写和回读块之间响应取消；清理时先等 Flash 空闲，再清模式位并锁定。
- 芯片识别与换板轮询不主动停核，避免暂停刚完成烧录的程序；仅实际擦写前停核。
- 真实任务改用 connectedDevice 前台服务；模拟任务继续 shortService。通知与实际任务模式一致。
- 复位失败/未解除停核不会计为成功；换板后写入前重新核对 UID、设备组与容量。
- 容量已知时提前拦截越界；未识别容量不再宣称固件适配 64 KB。配置错误不再归为 USB 或坏板。
- 跳过校验的任务明确显示“未校验”，以任务冻结结果显示校验与复位状态。

## 未验证与当前边界

- 未执行真实 USB / 控制板擦写；模拟器不能直接访问 Mac USB 上的 ST-LINK。
- 当前真实编程支持 F1 单 Bank、最大 512 KiB。0x430 的双 Bank 真实编程在擦除前拒绝；仍可探测/规划。
- 当前直接半字编程优先验证正确性，速度需实板测量。
- 不修改 Option Bytes，不自动解除读保护。

## 用户实测步骤

1. Android 10 或以上真机安装 `Corn-Flashing-0.1.6-test1.apk`。
2. 关闭模拟烧录器，接入 OTG / ST-LINK/V2 / 目标板，授权后点击“识别芯片”。
3. 导入这份用户 HEX。它超过 64 KiB，若目标报告仅 64 KiB，拒绝烧录是正确行为；不能强行绕过。
4. 初次实测使用“只擦用到的页”和“回读全部”，关闭自动换板后手动开始。
5. 失败时保留错误页截图和完整日志，以便区分 USB、探针固件、容量、擦除、写入、校验或复位阶段。
